# Core workflow

`src/alomancy/core/`: the active-learning skeletons, the loop machinery, starting data, dataset curation and model selection. User-facing guides: `docs/writing_a_workflow.md` (new skeletons), `docs/starting_a_run.md` (start modes), `docs/dataset_curation.md`.

## Entry point and skeletons

- **`ALomancy`** (`core/entry.py`) is the user-facing entry point, exported lazily from `alomancy/__init__.py` through module `__getattr__`. Never import `core` eagerly there: it must run after the `.expyre` seeding and `matplotlib.use("Agg")`. `ALomancy(path_or_dict)` loads a path with `load_dictionaries`, calls `build_workflow`, exposes `.workflow`/`.run()` and delegates other attributes to the workflow. `alomancy run config.yaml` is the CLI equivalent.
- **`build_workflow(jobs_dict)`** (`core/active_learning_workflow.py`, re-exported by `committee_uncertainty_workflow.py`) dispatches on `general.al_workflow` (default `"committee_uncertainty"`) through the registry's `"al_workflow"` category (`registry.py`, `workflow_class=...`). Constructing a skeleton class directly with a config naming a different skeleton raises `ValueError`: the config picks the architecture. Modules (trainer, generator, evaluator, initialiser) are resolved from the config through the same registry, never by subclassing.
- **`ActiveLearningWorkflow`** (abstract) owns everything generic. A concrete workflow declares `NAME`, `KWARGS_KEY`, `KWARGS_DEFAULTS`, `NEW_STRUCTURE_CONFIG_TYPE`, optionally `validate_settings()`, and implements only `run()`, which orders the steps.

Children:
- **`CommitteeUncertaintyWorkflow`** (`committee_uncertainty_workflow.py`): `general.committee_uncertainty_kwargs.num_of_models_in_committee` (default and minimum 3, validated at construction). `select_uncertain` = best model → `generate_candidates` → `predict` with the whole committee → `find_high_sd_structures`. The best model is predicted once, labelled `"base_mlip"`, every other model under its own `fit_i` label, so it isn't counted twice in the std-dev. New structures get `config_type="high_sd"`. `plot_loop` draws the committee plots.
- **`RandomSelectionWorkflow`** (`random_selection_workflow.py`): one model; `general.num_of_structures_per_loop` candidates chosen at random, seeded by `general.seed + loop`, saved to `structure_generation/random_selection_structures.xyz`; config_type `random_selection`. A baseline.
- **`NoveltySelectionWorkflow`** (`novelty_selection_workflow.py`): one model. `select_novel` describes candidates with redundancy removal's `char_vec_128` (`utils/remove_redundancy.descriptors_for_atoms`, built like `_prepare_for_storage` so it matches the DB cache; never stored), stacks them after every non-duplicate DB descriptor (`_cached_descriptors`), and uses deduplicate_lib's `binary_search_tolerance` (via `PerturbedDatasetReclustering`, `perturbations_per_vector=1`) on `_CandidateDistanceMatrix`, a `DistanceMatrix` whose unique count covers candidate rows only, to find the largest tolerance at which `DistanceMatrix` keeps at most `num_of_structures_per_loop` candidates. `DistanceMatrix` (deduplicate_lib >= 0.1.3) keeps rows in order, each unless it is within the tolerance of a row already kept; DB rows go first, so a candidate near the database is never kept and a cluster of candidates contributes its first member. More than n (no exact tolerance) is trimmed by nearest-neighbour distance; fewer is accepted. Saved to `structure_generation/novelty_selection_structures.xyz`; config_type `novelty_selection`.

## Parent helpers a `run()` calls

- `prepare_run()`: curation-policy check, `pre_run_checks`, resume or `_initialize_training_set` (cold/warm start), split filters + curation + redundancy; saves `results/run_config.yaml`; returns the first loop.
- `iterate_loops(start)`: yields `LoopContext(loop, base_name, workdir, train, test, train_only, plots_dir)`, writes `train_set.xyz`/`test_set.xyz`, skips loops with `loop.done`, sets the event loop tag (`set_current_loop`).
- `train_models(ctx, seeds, *, min_successful=1)` → `list[TrainedModel]`: one model per seed on one shared train/valid/test split, **one parallel `submit_n` batch**, per-fit caching, seed recorded in `training/fit_i/fit_seed.json` (a mismatch warns, it doesn't retrain), then the `results/best_model/` update.
- `seeds(n)`: `general.seed + i` (unchanged so cached fits stay valid). `best_model(models)`: `rank_committee`.
- `generate_candidates(ctx, model)`, `predict(ctx, models, structures)` (one parallel batch of `mlip/predict.predict_with_model`).
- `high_accuracy_evaluate(ctx, structures)`: sets `job_id` and `needs_relaxation` from `force_ceiling`, injects `force_ceiling` as `fmax`, runs DFT, then `clean_structures` with `NEW_STRUCTURE_CONFIG_TYPE` and `al_loop`.
- `add_to_dataset(ctx, structures)` (`test_ratio` split, or `fixed_test` diagnostics), `finish_loop(ctx)` (writes `loop.done`, the timing plot and the loop report).

Section names are fixed to their config keys (`_INITIALIZATION_NAME`, `_TRAINING_NAME`, ...); functions that still read `config["name"]` get it merged into a shallow copy at the call site. A `name` written in the config is ignored with a warning.

## `@phase` and restarts

`@phase(name, load=...)` wraps a loop step with a restart sentinel: if `results/<loop>/<name>.done` exists the step is skipped and `load(self, ctx, *args, **kwargs)` rebuilds its result from the files the step wrote (the decorator never stores return values); otherwise it runs and writes the sentinel after success. A phase may run once per loop (`_phases_run`); a second call raises unless given `phase_name="..."`. The decorator logs "Phase %s started for %s." and `_mark_phase_done` logs "Phase %s marked complete for %s." (parsed by the timing plot; keep the text), plus coded `phase_started`/`phase_completed` events, and sets the event phase tag.

The three loop phases: `train_mlip` (`_train_models_phase`; loader re-reads each `fit_i`), `generate_structures` (each child's selection step, e.g. `structure_generation/high_sd_structures.xyz`) and `high_accuracy_eval` (`high_accuracy_evaluate`; loader re-reads `high_accuracy_eval_results.xyz` through the evaluator's `read_existing_result` and relabels with `_label_new_structures`). The evaluator module also checks/writes `high_accuracy_eval.done` itself, because initialization calls it outside any loop. Sentinel and file names are unchanged from before the 1.0 split, so older results directories resume mid-loop; `tests/core_tests/test_committee_uncertainty_workflow.py::test_resumes_existing_mid_loop_results_without_redoing_work` guards this.

All results land under `results/<base_name>/` with a fixed layout; every step checks for its outputs before submitting anything, so a restart redoes only what's missing.

## Start-up checks

`pre_run_checks()`: `acquire_local_expyre_lock`, `ensure_ssh_connectivity` (`remote_submission.md`), then `display_workflow_summary()` (a per-phase settings summary flattened from each phase's job dict up to 2 levels, values the user wrote marked, plus the HPC profile table from `configs/hpc_profiles.py` with each host's installed alomancy version), then the PyPI version check: the installed `alomancy.version.__version_tuple__` against the latest release, warning one minor behind, `RuntimeError` one major behind. Skipped on network failure and under `ALOMANCY_TEST_MODE`/`ALOMANCY_MOCK_EXTERNAL`.

Construction-time validation (`ActiveLearningWorkflow.__init__`): `general.dataset_kwargs` must have `test_ratio` and `target_config_types` (`_DATASET_KWARGS_REQUIRED`); `general.redundancy_kwargs` is checked by `validate_redundancy_kwargs`; renamed/moved/removed keys raise with their new location (`_RENAMED_KEYS`, `_MOVED_KEYS`, `_REMOVED_KEYS`); unread keys warn (`configuration.md`); split filters are validated; a cold start without an `initialization` section raises.

## Starting data: `general.start_from`

`_parse_start_from` (`core/active_learning_workflow.py`) picks the mode from the keys present: `train_xyz` + `test_xyz` (import both, keeping the file-level split), `xyz` (a path or a list; imported, then split), `database` (import a **copy** of a former run's `GlobalDatabase` with `GlobalDatabase.import_from_database`: keeps `config_type`/`split`/duplicate and high-force flags, old `global_db_id` → `source_global_db_id`, model predictions dropped, the source never written), or none (cold start). More than one source, half a train/test pair, unknown keys, or `metadata_map` without an xyz source raise `ValueError` at construction.

Every mode then takes the same path in `_initialize_training_set`: `_import_start_data` (idempotent: xyz files by `source_dataset_sha256`, databases by `source_database`) → the initialiser's `compute_needs` → generate and DFT only the missing initialization targets (nothing at all when the config has no `initialization` section) → split → write `results/initialization/train_set.xyz`/`test_set.xyz`.

- xyz imports go through `utils/import_structures.normalize_metadata`: labels from `metadata_map`, then aliases (`type`/`label`/`config`, `energy`/`dft_energy`, `forces`/`dft_forces`, ...), then the attached calculator; missing `config_type` → `"external"`; missing energy/forces raise before anything is imported.
- Structures with any element outside `general.elements` are dropped at import (`filter_by_elements`, both modes, event `start_from_elements_excluded`), so redundancy removal and the filters never see them. Widening `elements` later won't re-import them: `GlobalDatabase.record_import` writes every source to `imported_sources.json` next to the DB, even when every structure was excluded, and `is_imported` also accepts the older per-structure markers.
- The source run's `split`, `global_db_id`, flags and `model_*` predictions are always dropped from xyz imports.
- A single-xyz start whose structures are all `"external"` (outside `target_config_types`) raises rather than producing an empty test set.
- The old entry points (`initial_train_file_path`/`initial_test_file_path`, `initialization.extra_datasets`, `skip_initialization`, `reset_extra_splits`) are in `_REMOVED_KEYS`.

## Train/test split

The split keeps any structure's existing `split` tag (pre-split files, imported databases) and applies the `test_ratio` rule (`_split_untagged`) only to untagged structures; other tags (e.g. `diagnostic`) stay out of both sets. `test_ratio` applies **only within the `target_config_types` pool** (e.g. `init_amorphous`, `init_MP`), never the whole DB: dimers, trimers, stretch/compress and `IsolatedAtom` never count. A quota over the whole DB could send all of a small target pool to test, and because `update_splits_post_hoc` never re-tags a tagged container, that config_type would be starved out of training forever. A backstop reserves one structure per config_type against an unlucky shuffle.

Generic split settings live in `general.dataset_kwargs` (`test_ratio`, `target_config_types` required; `valid_fraction`, `valid_config_types`, `grouped_splits`, `grouped_validation`, `fixed_test`); run control in `general` (`train_only`). Their old locations under `committee_uncertainty_kwargs` are in `_MOVED_KEYS`. `_select_validation_split` only warns and skips the validation carve-out when the eligible pool is too small. Splitting helpers for atom lists are in `utils/test_train_manager.py`.

## Curation after every dataset change

After initialization and after each loop, `_curate_dataset(base_name)` runs the train/test quality filters, then dataset curation (if configured), then redundancy removal. Redundancy goes last so it only compares structures still in the training set, with this loop's quality flags already set:

- **Redundancy** (`general.remove_redundancy`, default true; `general.redundancy_kwargs`; `utils/remove_redundancy.py`):
  - **Pool:** `_pool_indices` takes the structures in the training set (`global_database.is_in_training_set`: train split, not `is_duplicate`, not `is_quality_filtered`, `is_training_eligible`) whose config_type is in `target_config_types` + the workflow's `NEW_STRUCTURE_CONFIG_TYPE`. A structure already out of training never flags another. Flags are never cleared automatically (`GlobalDatabase.clear_duplicate_flags` undoes them by hand).
  - **Descriptors** (`char_vec`, `global_descriptor/atomic_distance_descriptor.make_char_vec`) are cached in the DB under a dimension-specific key (`char_vec_128`, `remove_redundancy.descriptor_key`) via `GlobalDatabase.store_descriptors`, computed once per structure.
  - **Flagging** uses deduplicate_lib's `DistanceMatrix` (>= 0.1.3): in DB order, each structure is kept unless it is within the tolerance of one already kept, so each group of near-duplicates keeps its earliest member. Before 0.1.3 it flagged every member of a group not containing row 0.
  - **Tolerance** (`probe_redundancy_tolerance`): `tolerance_sweep` counts the structures kept at `probe_steps_per_structure` × N tolerances (clamped to 20–2000) from 0 to the largest distance from the first structure, with the same `DistanceMatrix` rule. `choose_tolerance` takes the start of the lowest plateau (kept count unchanged over at least `_PLATEAU_MIN_STEPS` steps) that flags something and is at least `min_plateau_width` of the swept range wide. If that would flag more than `max_flagged_fraction` (default 0.5), nothing is flagged and `redundancy_cap_hit` is logged as a warning. No qualifying plateau: nothing flagged. `general.redundancy_kwargs.tolerance` skips the choice (outcome `fixed`). `validate_redundancy_kwargs` runs at construction. On a pairwise-distance descriptor, data without real duplicates usually has no plateau at small tolerances, so the cap is what stops a coarse plateau from flagging most of the data (the committee_mace_qe run flagged 96% before it).
  - **Record:** with `probe_path`, the sweep, plateaus, `chosen_tolerance`, `outcome` (`applied`/`fixed`/`no_plateau`/`cap_exceeded`), `settings`, `n_structures`, `n_flagged` and `descriptor` are saved to `results/<loop>/redundancy_probe.json`, which the loop report plots.
  - **Before DFT** (`ActiveLearningWorkflow.non_redundant_selector`, used by `CommitteeUncertaintyWorkflow.select_uncertain` through `find_high_sd_structures(select_indices=...)`): the probe runs on the current pool (`training_reference`), and `select_non_redundant` walks the candidates in ranking order, skipping any within the tolerance of the pool or of an earlier pick, so DFT isn't spent on structures the end-of-loop pass would flag (event `selection_redundant_replaced`). Off with `remove_redundancy: false` or when no tolerance qualifies.
- **Quality filters** (`general.train_filter` / `general.test_filter`, `utils/split_filter.py`), same schema: `max_force` (eV/Å; a max per-atom force norm ≥ value, or missing/non-finite forces, fails) and `formation_energy_per_atom` (`[min, max]` eV/atom, inclusive, either bound null = open; `(E − Σ E0[element]) / n` against the DB's `IsolatedAtom` energies, stored as `REF_formation_energy_per_atom_e0`). Defaults (`TRAIN_FILTER_DEFAULTS`/`TEST_FILTER_DEFAULTS`, merged under the user block by `resolve_split_filter`): train `max_force: 100`, everything else off; an explicit `null` disables a default. `apply_split_filter` runs before every redundancy pass and **rewrites `is_quality_filtered`/`quality_filter_reasons` on every container of the split each time**, so loosening a filter brings structures back. Failing structures stay in the DB; `get_train_atoms`/`get_test_atoms` skip them (`exclude_quality_filtered=True`). Structures with an element missing from the E0 dict aren't energy-filtered (one warning per call). The legacy `is_high_force` flag is ignored. Validated at construction (`validate_split_filter`).

## Training, retries and model selection

- **`train_models` retries failed fits once, and a fit only counts once it is evaluated** (`_train_models_phase`). After the first batch, every missing fit index is resubmitted once (same seed, same split files); then `min_successful` is checked (3 for the committee, 1 for single-model workflows): fewer raises `RuntimeError`, more-but-not-all logs "proceeding with N". Success is decided by `_collect_fit` exactly like the restart cache: every path in the trainer's `output_paths` exists and `read_existing_result` succeeds (checksum-verified). A job that returned but left no evaluation is logged "finished but was not evaluated" and retried like any failure. Seeds are recorded only for fits that pass. Fits are addressed by their own `fit_idx`, never re-derived from a range, so a retry never overwrites a good fit. Events: `fit_retry`, `fit_missing`, `fit_not_evaluated`.
- **`rank_committee`** (`mlip/evaluation.py`) is the single ranking rule, used by `best_model`, the MAE-vs-loop plot (`metrics_by_loop`) and `_update_best_model`. It reads each fit's `evaluation_metrics.json` through `read_evaluation`, which also requires the evaluated model to exist and match the SHA-256 recorded with the metrics. It ranks by metric (default `mae_f`) on the shared `"valid"` split when every fit has one, falls back uniformly to `"test"` when none has one, and raises `RuntimeError` if any fit lacks the split in use (including fits that disagree on having `"valid"`). There is no `fit_0` default; that once crashed MD when `fit_0` itself had failed.
- **`results/best_model/`** always holds the latest loop's best model: `_update_best_model` copies the ranked fit's `deployable_model_path` to `results/best_model/ALomancy_best_model<suffix>` (the trainer's own extension: `.model` for MACE, `.pth` for SevenNet) via a temp file + `os.replace`, deletes any other `*.model` / `ALomancy_best_model.*` there, and writes `model_metadata.json` (`al_loop`, `fit_idx`, `selected_on_split`, `model_file`, `trainer`, source path, sha256, per-split and per-`config_type` energy/force/stress errors). Missing evaluations or no deployable model warn and keep the previous best model.
- `check_quality_gate` (`mlip/evaluation.py`) optionally requires every committee member to meet per-domain `valid` limits on one shared validation set.

## DFT of new structures

`high_accuracy_evaluate` relaxes AL-generated structures (GO) until their max force is at most `high_accuracy_evaluation.force_ceiling` (default `100.0` eV/Å, `_DEFAULT_FORCE_CEILING`; `null` = single point only), passed to the evaluator as `fmax`. It's a cap, not a convergence target. It replaced the DFT half of the removed `general.high_force_threshold`; the other half is `train_filter.max_force`. Why: a cold-start model drives MD/EZGA into near-collision geometries with enormous single-point forces (median ~440 eV/Å, max ~1680 eV/Å observed) that the train filter then discards, so the training set stalls while the DB grows. Initialization structures keep their own `needs_relaxation`/fmax 0.05 policy.

`needs_relaxation` is never cleared automatically: it survives `atoms.copy()`, `clean_structures` and the DB, and MD frames inherit it from their seed. Any path with a deliberate relaxation policy (like `high_accuracy_evaluate`) must set it explicitly on its output.

## Provenance

`config_type` in `atoms.info` tracks where a structure came from (`init_dimer`, `init_MP`, `high_sd`, `random_selection`, `novelty_selection`, `external`, ...). The loop index is `atoms.info["al_loop"]`, set via `extra_metadata`; never embed it in the config_type (`"al_loop_N"`). `general.seed` (default 803) seeds every random choice.
