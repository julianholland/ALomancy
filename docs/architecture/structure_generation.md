# Structure generation

`src/alomancy/structure_generation/`: candidate generation (MD or EZGA) and committee-uncertainty selection. Generators are registered under `structure_generator` (`structure_generation.generator`, default `"md"`).

## Generators use the trained MLIP

`generate_candidates` passes the generator a `CalculatorSpec` (`mlip.md`), not a model path: plain data that pickles into remote jobs, since a live (often GPU-resident) calculator must not cross the ExPyRe boundary. `spec.build(device=None)` calls the trainer's `get_calculator` where the calculator is needed: on the node for MD (`md_wfl._run_md_with_spec`) and EZGA (`run_ezga`). `run_md` takes the calculator as a required argument and has no MACE fallback. The removed `md_kwargs.trainer`/`trainer_config` (default `"mace"`) made a SevenNet run hand its `.pth` to MACE (`'dict' object has no attribute 'to'` in every MD job); they're in `_REMOVED_KEYS`. `tests/core_tests/test_active_learning_workflow.py::test_md_explores_with_the_calculator_of_the_trained_mlip` guards this. MD and EZGA changes need a remote reinstall.

## Counts: generation vs selection

`structure_generation.num_of_structures_to_generate` is the candidate pool (MD: `snapshot_interval = steps × runs // to_generate`); `general.num_of_structures_per_loop` (default 50) is what every selector sends to DFT. `_resolve_structure_counts` (`ActiveLearningWorkflow.__init__`) defaults to_generate to 10 × per_loop, raises if to_generate < per_loop, and warns below 2 × per_loop (`few_candidates_configured`); `generate_candidates` warns when fewer than 2 × per_loop candidates survive the bond filter (`few_candidates_generated`). The old `desired_num_of_structures` is in `_MOVED_KEYS`.

## Bond filter

**No structure with a pairwise distance below 0.5 Å is scored or sent to DFT**: `filter_structures_by_min_bond_distance` (`utils/clean_structures.py`) runs in `generate_candidates`, before committee scoring, and again in the DFT orchestrator as a final net (which also covers initialization). `get_all_distances(mic=True)` is safe for every structure; single atoms pass.

## MD (`structure_generation/md/md_wfl.py`)

Settings live in `structure_generation.md_kwargs` (schema from `run_md`'s signature); seed selection in `md_kwargs.structure_selection_kwargs` (`num_of_md_starts`, `enforce_chemical_diversity`, `seed`); the generic seed filter (`chem_formula_list`, `selectable_configs`, `atom_number_range`) in `structure_generation.structure_selection_kwargs`.

- **Ensembles**: `ensemble: "nvt"` (default, fixed-cell `ase.md.langevin.Langevin`) or `"npt"` (`ase.md.langevinbaoab.LangevinBAOAB`, variable cell, targeting `pressure` in GPa). Anything else raises `ValueError`. **`externalstress` must never be `None` for NPT**: ASE only activates the barostat when it isn't `None`, so `None` silently runs fixed-cell dynamics with the costlier integrator. `run_md` passes `-pressure * ase.units.GPa`, so even `pressure=0.0` keeps the barostat on.
- **Seeds are reproducible, saved, and replaced once if their run never starts** (`generate`). `select_diverse_seeds` (`utils/seed_selection.py`) draws from `np.random.default_rng(seed)` (formulas sorted first), and the seeds are written to `structure_generation/md_seeds.xyz`: run `i` is always `md_output_i` with `seeds[i]`, and only runs with no output directory are submitted. A trajectory with fewer than `_MIN_FRAMES` (2) frames did no MD step and gets **one** replacement: an unused structure (by `geometry_digest`; a used one with a fresh `md_seed` if none are left), appended to `md_seeds.xyz` with `info["replaces"] = i` and run as a new index (sharing the original's `md_run_<slot>` item). Runs that stepped are kept however short; `run_md` appends frames as it goes and catches force/integration failures. The candidates cache (`<name>_generated_candidates.xyz`) is written only after the replacement round, from runs with ≥ 2 frames; if none have any, `generate` raises `RuntimeError` without writing the cache, so a restart retries. Events: `md_no_steps`, `md_unfinished`, `md_summary`.
- `select_initial_structures` (`structure_generation/select_initial_structures.py`) reuses structures with replacement when `num_of_md_starts` exceeds the filtered pool, giving each a distinct `info["md_seed"] = seed + i` that seeds Langevin's `rng` (so duplicated seeds don't produce identical trajectories); only an empty pool raises.
- Reloading `structure_generation_input_structures.xyz` reads with `index=":"` (a bare `read()` returns only the last frame) and regenerates if the count is short of `num_of_md_starts`, so a half-written file isn't trusted.
- **`md_kwargs.traj_interval`** (default off) writes `md_output_i/md_trajectory.xyz`, every n-th production step, via a `dyn.attach` observer that skips steps already written (ASE re-calls observers at each `dyn.run()`, and the snapshot loop runs in segments). Validated with `if`/`raise ValueError`.

## EZGA (`structure_generation/ezga/generate_structures.py`)

`generator: "ezga"` replaces candidate generation only; the bond filter, committee scoring and selection still apply to its output.

- **`ezga_kwargs` is EZGA's own config** (its `GAConfig` dict, what its YAML holds), plus two ALomancy keys popped before EZGA sees it: `structure_selection_kwargs` (`num_of_seeds`, default 8; `enforce_chemical_diversity`) and `local` (default false). User sections merge over `_EZGA_KWARGS_DEFAULTS` and `_default_kwargs` (`_merge`: dicts key by key at every level, lists such as `mutation_funcs` replace). The defaults follow the EZGA wiki's MLIP active-learning example (`Examples/MLIP-Active-Learning`, its slab-specific objectives and constraints left out): `multiobjective.size` 100 with `composition_repulsion_weight` 1.0, thermostat 0.05 (constant), `collision_factor` 0.6, full relaxations (`fmax` 0.05, `steps_max` 100). `max_generations`, when not set, is `max(5, ceil(2 × num_of_structures_to_generate / size))`. Every species comes from `general.elements`: rattle, random_strain, a `bounded_mutation_add` and a `bounded_mutation_remove` per element, a `mutation_swap` per ordered element pair; composition feature `IDs`; `objective_energy_per_atom`. The add/remove limits come from `structure_generation.structure_selection_kwargs.atom_number_range` (unbounded if unset, and always unbounded with a `hise:` block: the range is sized for the seeds and HiSE tiles them into larger cells, where it would refuse every add and remove; `validate_kwargs` warns `ezga_atom_range_seeds_only` when both are set without user `mutation_funcs`). Fully relaxed small cells often fall back into known minima, which EZGA's duplicate filter drops, so a search can yield well under `max_generations × size` new structures.
- **ALomancy owns** `output_path`, `resume` (always false: in ezga-lib 1.2 resume only advances the generation counter), `rng` (`general.seed`), `population.dataset_path`/`db_path`/`db_ro_path`/`storage`, and the model: `simulator.calculator` holds only `ase_calculator` settings (`fmax`, `steps_max`, `nvt_steps`, ...), and `run_ezga` wraps the best model's calculator (`CalculatorSpec.build()` on the node) in EZGA's `ase_calculator` with them. Setting an owned key raises; the 1.0.3 keys (`population_size`, `mutation_operators`, `min_atoms`, `max_atoms`) raise naming their new home.
- **Checked at construction** by the registry hook `validate_kwargs` (called from `ActiveLearningWorkflow._validate_generator_kwargs`): owned/removed keys, species outside `general.elements`, unknown `ase_calculator` settings, then `ezga.factory.load_config` on the full config with a placeholder calculator, so EZGA's pydantic schema (unknown keys rejected) and every factory import are checked at startup. `max_generations × multiobjective.size` below `num_of_structures_to_generate` raises; below twice it warns (`ezga_few_structures_configured`). The resolved config is stored back in `structure_generation.ezga_kwargs`, so the summary and `generate()` see it. The schema keeps `ezga_kwargs` `OPEN`.
- **HiSE** (EZGA's supercell escalation) runs when the user writes a `hise:` block: `run_ezga` calls `ezga.hise.manager.run_hise` and returns the last stage's directory (`supercell_{a}_{b}_{c}[_suffix]`, where that stage keeps its database), which is what's read. `hise.overrides` may not set owned keys; `hise.overrides["simulator.calculator"]` is one dict of `ase_calculator` settings per stage, merged over `simulator.calculator` and wrapped around the model, e.g. the wiki's last-stage MD burst `{nvt_steps: 40, T: [300, 600]}`. The count check uses the last stage's `max_generations` and `multiobjective.size`.
- **No YAML round trip**: the config goes to `load_config` as a dict (deep-copied: it mutates its input) with the live calculator in place, so nothing ALomancy owns is passed through EZGA's string-to-import resolution.
- **Seeds**: at most `num_of_seeds` from the eligible structures via `select_diverse_seeds` (capped at the pool size, never padded), saved to `structure_generation/ezga_seeds.xyz` and reused on restart.
- **Runs as one remote job** (`submit_n(run_ezga, ...)` on `structure_generation.hpc`, staging back the `ezga/` directory), or in-process with `local: true`. Remote reinstall needed after changes.
- **Candidates come from EZGA's database**, the sage_lib hybrid storage at `ezga/db`, or with HiSE the last stage's directory (`database/global_database.read_storage`, read-only; `atoms_from_container(labels=False)`: geometry only, never `REF_*`, since its energies are the model's). Its `"dataset"` partition accumulates the seeds and every unique, valid evaluated structure; `read_offspring` keeps those with a `generation` (the seeds have none) from the newest `run_uid` (a HiSE stage's database also holds earlier stages' structures, carried with their old `run_uid` and generation numbers), as `info["ezga_generation"]`, `ezga_operation`, `ezga_energy`. `most_recent` takes `num_of_structures_to_generate` of them, newest generations whole first, sampling (seeded) only the oldest generation needed. EZGA's own duplicate filter stays on by default. Event `ezga_summary`.
- **Restart**: `ezga/ezga_candidates.xyz` (written last, read with `read_xyz`) is the sentinel. An `ezga/` directory without it is an unfinished search: it is moved to `ezga.failed_<stamp>` (event `ezga_restarted`) because EZGA appends to an existing database. A failed job or a search with no offspring raises without caching.
- Output: `results/<base>/structure_generation/ezga_seeds.xyz`, and in `ezga/`: `initial_population.xyz`, `db_ro`, then either `db` plus EZGA's `generation/` and logs, or one `supercell_<a>_<b>_<c>/` directory per HiSE stage (database, `generation/`, `metadata.json`, logs); `ezga_candidates.xyz` last. User-facing walkthrough: `docs/ezga.md`.

## Committee uncertainty selection

`find_high_sd_structures` (`structure_generation/find_high_sd_structures.py`, polars) selects the candidates with the largest force standard deviation across the committee and saves `std_dev_forces.csv`. It takes the count as `num_of_structures`; when fewer candidates survive than requested it warns (`fewer_candidates`) and selects them all. `select_indices(ranked, n)` replaces the plain top-n cut; the committee workflow passes `non_redundant_selector` (`core_workflow.md`, redundancy) so picks redundancy removal would flag are replaced by the next candidates; if it keeps fewer than requested (possibly none) that logs `selection_redundant_shortfall`. The selection is recorded in `std_dev_forces.csv`'s `selected` column (the report's selection cut). `high_sd_structures.xyz` is always written, empty for an empty selection, and read back through `read_selection` (`utils/file_saving_and_parsing.read_xyz`, which reads an empty file as no structures; the DFT phase's cached results use it too). Only an empty list or a count ≤ 0 raises.
